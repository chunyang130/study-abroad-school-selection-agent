# 留學選校顧問 Agent（Claude Skill）

> A Claude Agent Skill for study-abroad school selection: structured intake, evidence-based tiering against historical admission data, strict first-party-source rules to prevent hallucination, and a validated Excel deliverable.

把留學顧問「背景評估 → 科系討論 → 判讀落點 → 產出選校表」的流程，做成可重複使用的 Claude Agent Skill。
這個工具我在工作上實際使用，**選校表的資料整理時間由約 2 小時縮短到約 10 分鐘，試作的選校表 0 筆錯誤資料**，前端顧問可以直接點連結審閱。

本 repo 為公開版：公司名稱、內部檔案路徑與真實錄取榜單已移除，附錄換成虛構範例；Agent 的流程與規則與實際使用的版本相同。

## 要解決的問題

做一份美國碩士選校表，顧問要逐校查排名、門檻、TOEFL、截止日、學費，一份 20 所的表很容易花掉半天，而且有兩個風險：

1. **資料來源不一**：網路上的代辦網站、排名整理文章常是舊資料或錯的
2. **落點靠感覺**：夢幻／合適／低風險的判斷因人而異，學生也不知道依據是什麼

一般的 AI 聊天會直接「回答」排名和學費，但數字可能是編的。所以這個 Agent 的重點不是會回答，而是**只用可查證的來源回答，查不到就說查不到**。

## Agent 的架構

| 元件 | 內容 |
| --- | --- |
| 指令（SKILL.md） | 角色與職責範圍、7 個階段的工作流程、填表與查證規則 |
| 知識庫 | 公司歷年錄取榜單（公開版為虛構範例）、TOEFL 新舊制換算表 |
| 工具 | 網頁讀取查官網；動態網頁（例如 US News、Kaplan Degree Finder）改用瀏覽器實際操作 |
| 產出 | 選校表 xlsx（初選表／終選校表＋資料來源工作表）、交接後端顧問的摘要 |

**工作流程**：招生介紹 → 背景評估 → 科系討論 → 用榜單判讀落點 → 選校討論 → 產出選校表 → 交接後端顧問

職責範圍也寫進指令：SOP、CV、推薦信、網申等後端工作一律不代寫，避免 Agent 越界。

## 我設計的規則

規則來自我和顧問團隊的實際作業經驗，由我整理成 Agent 指令。

**1. 落點判讀要有證據**

每一所學校都要先找榜單中「相近背景」的錄取案例（同領域、學校層級、GPA、語言成績），再對照學校官網門檻，最後才分層：

| 分層 | 判斷依據 |
| --- | --- |
| 夢幻 | 榜單錄取者明顯強於學生；或無相近案例且排名前段；或學生缺先修課 |
| 合適 | 榜單有相近背景案例，學生達官網門檻但優勢不明顯 |
| 低風險 | 榜單有背景相近或較弱的學生直接錄取，且學生明顯高於門檻 |

判斷依據要寫在表上，例如「榜單：私立大學資工 3.5/4.0、TOEFL 95 直接錄取」。**絕不捏造錄取率、平均 GPA 或錄取案例**；沒有相近案例就寫「榜單無相近案例」。

**2. 只用首要來源（防 AI 幻覺的核心）**

| 資料 | 唯一可用的來源 |
| --- | --- |
| 美國學校排名 | US News 官網 |
| 其他國家排名 | QS 官網 |
| 門檻、截止日、學分、課綱 | 該學校自己的官網 |
| 學費 | 學校學費頁或 Bursar 學費表 |

明列**禁止使用**的來源：代辦網站、論壇、部落格、排名整理文章、學校新聞稿轉述的排名。搜尋結果只能拿來找官網網址，不能拿來填數字。查不到就填「官網未列」，並連到最接近的官網頁面。

**3. 交付前查證**

- 確認頁面是學生入學年度的版本，不是去年的頁面
- 確認學程仍在招生（實際遇過學程停招，要改列官網推薦的替代學程）
- 每個數字附原始頁面連結，「資料來源」工作表寫出版本與查證日期
- 逐一測試連結能開、頁面標題是對的學程

**4. 處理容易出錯的細節**

- TOEFL 2026 年改成 1–6 分新制，新舊制要換算後才能比較；學生分數落在門檻附近時不直接判定，寫「接近門檻，建議向學校確認」
- 以「=」開頭的排名（例如 QS 的 `=40`）會被 Excel 當成公式，一律改寫成 `40=`

## 執行選校表產生程式

`build_school_list.py` 依 SKILL.md 的格式產出 xlsx。我另外把 SKILL.md 的交付前檢查規則寫成程式：校數與分層比例、必填欄位不可空白、學程必須附連結、不可有被當成公式的儲存格。檢查沒通過就不產出檔案。

```bash
pip install -r requirements.txt

# 正常範例
python3 build_school_list.py --input examples/sample_student.json --out output/initial_list.xlsx
# → 檢查通過，已產出 output/initial_list.xlsx（初選表，6 所：{'夢幻': 2, '合適': 2, '低風險': 2}）

# 故意放了 4 個錯誤的範例
python3 build_school_list.py --input examples/sample_with_errors.json --out output/bad.xlsx
# → 檢查未通過，未產出檔案：
#  - 分層 {'夢幻': 3, '合適': 1, '低風險': 2} 與預設 {'夢幻': 2, '合適': 2, '低風險': 2} 不同
#  - Example University D：「學費」空白，查不到請寫「官網未列」
#  - Example University E：「綜合排名」以 = 開頭會被 Excel 當成公式，請改寫（例：40=）
#  - Example University F：科系要附學程官網連結
```

## 在 Claude 中使用這個 Skill

把 `SKILL.md` 放進一個資料夾，在 Claude 的 Skills 設定上傳後，對話中提到選校、背景評估就會自動套用。實際使用時，把附錄換成自己機構去識別化後的錄取資料。

## 學到的事

- 要防 AI 幻覺，最有效的不是叫它「小心」，而是**明確列出可用和禁用的來源**，並規定查不到時要怎麼寫
- 規則要附真實踩過的例子（例如哪個學程停招、哪個網址會出錯），Agent 才知道要檢查什麼
- 交付格式要寫到欄位層級，產出才能直接給同事用，不用再整理
